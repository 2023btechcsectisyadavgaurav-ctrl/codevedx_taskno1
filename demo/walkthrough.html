Architecture

Everything lives inside one GCP project, tagged with common labels.

Users reach a single global load balancer with a static IP.

It sends traffic only to healthy web servers, spread across three zones.

The VMs have no public IP. Cloud NAT gives them outbound-only internet.

A least-privilege service account can only write logs and read one private bucket.

Security in code

Locked down by default

modules/security/main.tf
resource "google_compute_firewall" "allow_lb_http" {
  direction     = "INGRESS"
  source_ranges = [
    "130.211.0.0/22",   # Google LB only
    "35.191.0.0/16",
  ]
  target_service_accounts = [sa.email]
  allow { protocol = "tcp", ports = ["80"] }
}

# everything else: explicit logged deny
resource "google_compute_firewall" "deny_all" {
  priority = 65000
  deny { protocol = "all" }
}
modules/compute/main.tf
resource "google_compute_instance_template" "web" {
  # no access_config block => no public IP
  network_interface {
    subnetwork = var.subnetwork_self_link
  }

  shielded_instance_config {
    enable_secure_boot          = true
    enable_vtpm                 = true
    enable_integrity_monitoring = true
  }

  metadata = {
    enable-oslogin         = "TRUE"
    block-project-ssh-keys = "TRUE"
  }
}

Firewall: HTTP is allowed only from Google's load balancer ranges. Everything else is denied and logged.

VMs have no public IP, use Shielded VM, OS Login, and block project-wide SSH keys.

SSH is possible only through Identity-Aware Proxy. The bucket enforces no public access.

High availability and scaling

Survives a zone failure, grows with load

modules/compute/main.tf
resource "google_compute_region_instance_group_manager" "web" {
  distribution_policy_zones = var.zones
  # a, b and c: VMs spread evenly

  auto_healing_policies {
    health_check      = health_check.http.id
    initial_delay_sec = 180
  }

  update_policy {
    type            = "PROACTIVE"
    # rolling updates keep capacity up
    max_surge_fixed = length(var.zones)
  }
}
autoscaler + variables.tf
resource "google_compute_region_autoscaler" "web" {
  autoscaling_policy {
    min_replicas = 3
    max_replicas = 6
    cpu_utilization { target = 0.6 }
  }
}

variable "min_replicas" {
  validation {
    condition = var.min_replicas >= 2
    error_message = "at least 2 required"
  }
}

VMs are distributed across zones, and failed VMs are automatically replaced.

The autoscaler adds VMs when CPU passes 60%, up to a maximum of six.

Validation rules refuse single-zone or single-VM setups, so HA can't be configured away.

Deploying

Six commands from code to running platform

terminal
$ gcloud auth application-default login
$ cp terraform.tfvars.example terraform.tfvars  # set project_id
$ terraform init
$ terraform plan      # 27 resources to add
$ terraform apply     # builds everything
$ terraform output application_url   # open it in the browser
$ terraform destroy   # removes it all when finished

Authenticate, set your project ID, then initialize and preview the plan.

Apply creates the full stack. The load balancer URL is printed as an output.

Destroy removes everything, so there are no lingering costs.
